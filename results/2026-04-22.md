# 2026-04-22 测试结果：8 RS HDFS WAL 模式 3 Pod 压测

## 测试目标

验证 **HDFS WAL 模式**（WAL 写 Core 节点本地 HDFS）与前几轮 **EMR WAL 模式**（WAL 写 S3）的性能差异，以及 8 RS 集群在 HDFS WAL 下的稳定写入能力。

### 写入模式特征

- **停顿特征**：每次 MemStore flush 触发 blocked，持续约 **60~90 秒**，期间 ops/sec = 0，且出现 `INSERT-FAILED` 重试
- **停顿占比**：约 60~70% 的时间处于停顿/重试状态
- **恢复后瞬时峰值**：~53,000 ops/sec（Pod1+Pod2 合计，Pod0 相对偏慢）

## 关键结论

1. **HDFS WAL 单 Pod 瞬时写入速度约为 EMR WAL 的 2.3 倍**：WAL 写本地磁盘（HDFS）比写 S3 延迟更低，单次写入更快。

2. **HDFS WAL 停顿时间更长**：flush 写 S3 HFile 时阻塞更集中，每次 blocked 60~90 秒（EMR WAL 约 30~60 秒）。全程有效写入时间仅约 30~40%。

3. **全程平均吞吐被停顿严重拉低**：去掉停顿的纯有效写入时间内，峰值 ~53,000 ops/sec（3 Pod）相当于每 RS 约 ~20,000 ops/sec，高于 EMR WAL 的 ~17,000 ops/sec/RS。

4. **WAL 模式选择建议**：
   - 追求**低延迟、快速单次写入**：HDFS WAL
   - 追求**稳定、无周期性抖动**：EMR WAL（flush 不阻塞写入路径）
   - 生产场景（数据可靠性优先）：建议 EMR WAL + numgroups=4
